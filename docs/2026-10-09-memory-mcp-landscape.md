# Memory MCP landscape — nên gì / không nên gì cho second-brain MCP server

> Khảo sát ngày 2026-10-09. Nguồn **primary**: official docs, repo/source code, spec, issue tracker của chính dự án (không dùng blog tóm tắt). Bối cảnh: quyết định mind-runner (local-first, single-user, Go + SQLite) xây gì tiếp / không xây gì. Fact và ý kiến suy ra được tách nhãn ở mục 4; mục 5 ghi rõ "cần kiểm tra" khi chưa xác minh trực tiếp trong repo.

## 2. Guidance chính thức (Anthropic + MCP spec + Claude memory)

**Anthropic — tool design** ([writing-tools-for-agents](https://www.anthropic.com/engineering/writing-tools-for-agents)):
- "More tools don't always lead to better outcomes." → nên **gộp chức năng**: "Tools can consolidate functionality, handling potentially multiple discrete operations"; "Namespacing (grouping related tools under common prefixes) can help delineate boundaries".
- Output phải bounded: dùng "some combination of pagination, range selection, filtering, and/or truncation"; "we restrict tool responses to 25,000 tokens by default". Khi bị cắt phải hướng dẫn model thu hẹp query, không để "stranded".
- Error message phải "clearly communicate specific and actionable improvements" (không dump stack trace).
- Eval: "Start by generating lots of evaluation tasks, grounded in real world uses."

**Anthropic — context engineering** ([effective-context-engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)):
- "Context, therefore, must be treated as a finite resource with diminishing marginal returns."; "LLMs have an 'attention budget'".
- Ưu tiên just-in-time: giữ nhẹ context, "dynamically load data into context at runtime using tools" thay vì nạp sẵn.
- Structured note-taking là pattern chính thức: agent "writes notes persisted to memory outside of the context window" để nối phiên.
- Cảnh báo tích luỹ vô hạn: memory dài hạn bị "subject to context pollution and information relevance concerns"; agent bị "stale indexing" nếu không dọn định kỳ.

**Anthropic — building effective agents** ([building-effective-agents](https://www.anthropic.com/engineering/building-effective-agents)):
- "finding the simplest solution possible"; "Carefully craft your agent-computer interface (ACI)"; "Tool definitions and specifications should be given just as much prompt engineering attention as your overall prompts."

**MCP spec — tools** ([spec 2025-06-18/server/tools](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)): tool gồm `name, title, description, inputSchema, outputSchema, annotations`; list có pagination qua cursor; annotations `readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint` là "optional properties describing tool behavior"; "Clients SHOULD prompt for user confirmation on sensitive operations".

**MCP spec — security best practices** ([spec/security_best_practices](https://modelcontextprotocol.io/specification/2025-06-18/basic/security_best_practices)): "MUST NOT accept any tokens that were not explicitly issued for the MCP server.", "MUST NOT use sessions for authentication.", session ID "secure, non-deterministic", ưu tiên server-side DB cho dữ liệu nhạy cảm; least-privilege scope model; local server "MUST implement proper consent mechanisms prior to executing commands".

**Claude Code memory** ([code.claude.com/docs/en/memory](https://code.claude.com/docs/en/memory)): scopes user/project/local, "All discovered files are concatenated into context rather than overriding each other"; subdirectory CLAUDE.md load on-demand khi agent đọc/ghi file trong đó; "target under 200 lines per CLAUDE.md file"; auto memory: "auto memory lets Claude accumulate knowledge across sessions without you writing anything" nhưng **có bộ lọc**: "Claude skips anything it can derive from the codebase... It also skips anything your CLAUDE.md files already say."; MEMORY.md — "The first 200 lines..., or the first 25KB, whichever comes first, are loaded at the start of every conversation." (Docs hiện tại không còn mô tả phím tắt `#`; cách ghi là nói tự nhiên, ví dụ "add this to CLAUDE.md".)

**Claude apps memory** ([support article](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context), [blog](https://claude.com/blog/memory)): tự động + "remember this"; project có memory space riêng; incognito không lưu; auto-loại trừ "government ID numbers, criminal history, financial account numbers, and immigration status" và "By default, Claude does not store topics related to personal or sensitive subject matter"; user xem/sửa/xoá được, disable có 2 chế độ (giữ nhưng không dùng / xoá vĩnh viễn); "Memory isn't available to organizations with HIPAA, public-sector, or custom data retention agreements."

## 3. Thực tế vận hành — gì hiệu quả, gì thất bại (quan sát từ issue tracker / maintainer)

- **Đọc toàn bộ store là anti-pattern có thật**: issue #3959 xin thêm "lightweight read modes" cho `read_graph`/`search_nodes`/`open_nodes` "to address context explosion in deployments" ([issue #3959](https://github.com/modelcontextprotocol/servers/issues/3959)); search reference server chỉ substring, không ranking, scale tuyến tính theo graph ([index.ts](https://github.com/modelcontextprotocol/servers/blob/main/src/memory/index.ts)).
- **Nhiều process chung một file store ⇒ mất dữ liệu âm thầm**: "Two server processes sharing one MEMORY_FILE_PATH still discard each other's writes, silently." ([issue #4797](https://github.com/modelcontextprotocol/servers/issues/4797)); path cấu hình bị ignore khi chạy npx ([issue #692](https://github.com/modelcontextprotocol/servers/issues/692)); #4117 (22 comment) đề xuất quota, redaction, approval flow, guardrails cho destructive ops ([issue #4117](https://github.com/modelcontextprotocol/servers/issues/4117)).
- **mem0 đã bỏ UPDATE/DELETE trong write path**: paper v2 mô tả ADD/UPDATE/DELETE/NOOP + graph đánh dấu invalid thay vì xoá ([paper](https://arxiv.org/abs/2504.19413)); v3 README: "Single-pass ADD-only extraction -- one LLM call, no UPDATE/DELETE. Memories accumulate; nothing is overwritten." ([README](https://github.com/mem0ai/mem0)). Cái giá hiện rõ trong vận hành: #4956 (open, 20 comment) — "contradictory memories accumulate over time instead of the newer fact superseding the older one" ([issue #4956](https://github.com/mem0ai/mem0/issues/4956)); xoá bỏ sót entity index để lại stale links ([issue #7226](https://github.com/mem0ai/mem0/issues/7226)). Benchmark (LoCoMo 92.5, LongMemEval 94.4, BEAM 64.1) là số của hosted: "open-source users should expect directionally similar gains but not identical numbers" ([README](https://github.com/mem0ai/mem0)).
- **Graphiti chọn invalidate thay vì xoá**: "explicit bi-temporal tracking with automatic fact invalidation" ([README](https://github.com/getzep/graphiti)); Zep paper báo "accuracy improvements of up to 18.5% while simultaneously reducing response latency by 90%" trên enterprise dataset ([paper](https://arxiv.org/abs/2501.13956)). Nhưng chất lượng phụ thuộc extraction: README cảnh báo smaller local models "occasionally struggle with reliable structured output generation"; maintainer phải sửa chunking cho episode dài (LLM timeout, invalid JSON — [PR #1129](https://github.com/getzep/graphiti/pull/1129)) và dedupe node canonical ([#936](https://github.com/getzep/graphiti/pull/936)).
- **mem0 paper tự nhận giới hạn của graph**: graph variant có overhead multi-hop, chậm hơn dense text, và "raw full-context methods retain a narrow accuracy edge" ([paper](https://arxiv.org/abs/2504.19413)) — dựng graph để tối ưu có thể là premature.
- **File-as-source-of-truth cần máy móc reconciliation**: Basic Memory có bug tạo ghost entry khi move chưa commit ([#1152](https://github.com/basicmachines-co/basic-memory/pull/1152)), phải fail-closed cho "stale or cross-project external matches" ([#1141](https://github.com/basicmachines-co/basic-memory/pull/1141)), thiếu trace để debug score/index readiness ([#1250](https://github.com/basicmachines-co/basic-memory/pull/1250)); vector index tắt mặc định ([README](https://github.com/basicmachines-co/basic-memory)).
- **Cline Memory Bank = chi phí kỷ luật**: docs bắt buộc đọc toàn bộ file mỗi task ([docs](https://docs.cline.bot/prompting/cline-memory-bank)) nhưng issue thực tế: treo khi update memory bank ([#10951](https://github.com/cline/cline/issues/10951)), agent báo đã ghi mà file không đổi ([#1911](https://github.com/cline/cline/issues/1911)), mất protocol sau task ([#2097](https://github.com/cline/cline/issues/2097)).
- **Letta/MemGPT chuẩn hoá "paging" + background reorg**: memory pressure chèn "a system message into the queue warning the LLM" để agent tự dọn; "Memory edits and retrieval are entirely self-directed" ([paper](https://arxiv.org/abs/2310.08560)). Sleep-time compute: "Reasoning during sleep time transforms 'raw context' into 'learned context'", chạy nền, "modifies the memory in an 'anytime' fashion", claimed "Pareto improvement" ([blog](https://www.letta.com/blog/sleep-time-compute/)); docs hiện tại có dreaming với "Agent reviews before applying" và backup trước khi split file lớn ([memory docs](https://docs.letta.com/configuration/memory/)).
- **Bộ lọc lúc ghi là hành vi chính thức của Claude** (không chỉ là tối ưu): Claude Code skip thông tin suy ra được từ codebase ([docs](https://code.claude.com/docs/en/memory)); Claude apps loại nhóm nhạy cảm ([support](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context)).

## 4. Nên / Không nên (tổng hợp; ✔ = fact có nguồn, ~ = ý kiến suy ra)

**NÊN:**
1. ✔ **Tool surface nhỏ, gộp chức năng, tên rõ, có namespace** — "More tools don't always lead to better outcomes." ([writing-tools](https://www.anthropic.com/engineering/writing-tools-for-agents)).
2. ✔ **Write path chính là explicit tool call + trigger người dùng; auto-extraction phải có bộ lọc** — Claude apps vừa auto vừa "remember this" ([support](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context)); Claude Code auto memory tự skip thứ suy ra được ([docs](https://code.claude.com/docs/en/memory)); mem0 v3 chỉ ADD rồi để user sửa tay ([README](https://github.com/mem0ai/mem0)).
3. ✔ **Read path on-demand và bounded** — limit + ngưỡng điểm + pagination/truncation, kèm thông báo khi bị cắt ([writing-tools](https://www.anthropic.com/engineering/writing-tools-for-agents)); không có bound là nguyên nhân issue #3959.
4. ✔ **Reconciliation/consolidation chạy nền, không chặn ghi** — mem0 v3 một LLM call ([README](https://github.com/mem0ai/mem0)); Letta sleep-time "anytime" ([blog](https://www.letta.com/blog/sleep-time-compute/)); không có nó thì stale/contradictory tích tụ ([mem0 #4956](https://github.com/mem0ai/mem0/issues/4956)).
5. ✔ **Giữ temporal semantics** (as_of / validity / ưu tiên bản mới khi mâu thuẫn) kể cả khi policy là xoá cứng — Graphiti/Zep bi-temporal vì lý do này ([README](https://github.com/getzep/graphiti), [paper](https://arxiv.org/abs/2501.13956)). ~ Với mind-runner: giữ ít nhất `as_of` và ưu tiên note mới trong recall.
6. ✔ **User/owner kiểm soát được memory**: xem, sửa, xoá, tạm dừng ([support](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context), [blog](https://claude.com/blog/memory)).
7. ✔ **Không lưu secrets; redaction trước egress; least-privilege; consent khi chạy local** ([security practices](https://modelcontextprotocol.io/specification/2025-06-18/basic/security_best_practices)); Claude apps chủ động loại nhóm dữ liệu nhạy cảm ([support](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context)).
8. ✔ **Eval grounded vào việc thật** cho cả extraction và retrieval ([writing-tools](https://www.anthropic.com/engineering/writing-tools-for-agents)).
9. ✔ **Concurrency tường minh khi nhiều client mở cùng store** — #4797 mất dữ liệu âm thầm ([issue](https://github.com/modelcontextprotocol/servers/issues/4797)); dùng tool annotations (`destructiveHint`...) để client biết tool nào nguy hiểm ([tools spec](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)).

**KHÔNG NÊN:**
1. ✔ **Không làm tool kiểu dump toàn kho** (`read_graph`) hay list không phân trang ([#3959](https://github.com/modelcontextprotocol/servers/issues/3959); [writing-tools](https://www.anthropic.com/engineering/writing-tools-for-agents)).
2. ✔ **Không đẩy pipeline LLM UPDATE/DELETE phức tạp vào sync write path** — mem0 từng làm (paper ADD/UPDATE/DELETE/NOOP) rồi bỏ ở v3 còn "one LLM call" ([paper](https://arxiv.org/abs/2504.19413), [README](https://github.com/mem0ai/mem0)). ~ Cần chống trùng/mâu thuẫn thì để job nền.
3. ✔ **Không append vô hạn, không bỏ retention/purge** — tích luỹ bị Anthropic gọi đích danh là "context pollution" / "stale indexing" ([context-eng](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)); xoá không kỹ để lại index stale ([mem0 #7226](https://github.com/mem0ai/mem0/issues/7226)).
4. ✔ **Không bắt đọc toàn bộ memory mỗi phiên** khi store đã lớn (pattern Cline: "read ALL memory bank files at the start of EVERY task") ([docs](https://docs.cline.bot/prompting/cline-memory-bank)).
5. ✔ **Không tự động lưu mọi thứ** — phải skip thông tin suy ra được/trùng và nhóm nhạy cảm ([cc-memory](https://code.claude.com/docs/en/memory), [support](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context)).
6. ✔ **Không dựng knowledge graph trước khi chứng minh nhu cầu** — graph tốn extraction, chậm hơn dense text, có overhead multi-hop ([mem0 paper](https://arxiv.org/abs/2504.19413)); extraction phụ thuộc chất lượng model ([graphiti README](https://github.com/getzep/graphiti)). ~ Flat notes + hybrid search + rerank là mặc định lành mạnh; graph là optional.
7. ~ **Không phụ thuộc model local nhỏ cho structured extraction mà không có fallback/kiểm soát** — nguồn gián tiếp: Graphiti README cảnh báo small local models ([README](https://github.com/getzep/graphiti)) và Zep phải adaptive chunking ([#1129](https://github.com/getzep/graphiti/pull/1129)); mind-runner policy local — cần kiểm tra eval riêng (repo có `make eval-extract`).

## 5. Đối chiếu nhanh mind-runner

- **Đang khớp**: tool surface 9 tool gộp theo capability (remember/recall/task_*/ingest/briefing/export/forget) — đúng hướng "consolidate tools" ([tools.go](../internal/server/tools.go)); write path explicit + trigger `mind:`/`mind recall:`... + MCP instructions, hook capture chỉ optional ([README](../README.md)); có eval thật cho recall (recall@10/MRR) và extract. ✔
- **Đang khớp các pattern "chống thất bại"**: background pipeline (embed/extract/consolidate tuần) không chặn tool call — cùng hướng mem0 v3 / Letta sleep-time; retention + purge + backup 7 bản nên không append vô hạn ([README](../README.md)). ✔
- **Khác có chủ đích, cần nhận thức**: hard-delete (không supersede, không invalidate-window như Graphiti/Zep) — có backup + consolidate bù trừ, nhưng mất khả năng "fact cũ vẫn tra cứu được" mà bi-temporal cho; đánh đổi này hợp lệ cho personal store (suy luận). Không có knowledge-graph entities/relations (flat notes + meta + FTS/vector) — phù hợp guidance simplicity; nếu sau này muốn graph, tham chiếu data model Graphiti thay vì tự nghĩ ([graphiti README](https://github.com/getzep/graphiti)).
- **Đã kiểm tra trong repo (2026-10-09)**:
  - Tool annotations: ✔ có — `ReadOnlyHint` cho recall/task_list, `IdempotentHint` cho remember/task_add/ingest/export, `DestructiveHint` cho forget; task_update và briefing chưa có (briefing đổi gate ngày nên không read-only) ([tools.go](../internal/server/tools.go)).
  - Concurrency: ✔ WAL + `busy_timeout(5000)` + 1 connection/process; ghi nhiều bước dùng `BEGIN IMMEDIATE` ([store.go](../internal/store/store.go), [raw.go](../internal/store/raw.go), [purge.go](../internal/store/purge.go)).
  - Output bound: ~ recall cắt theo `limit` (mặc định 5) trên pool rerank top-20; briefing có `token_budget` 1500. Chưa có trần byte tường minh cho từng hit/export — chấp nhận được vì export ghi ra file, không trả vào context.
  - Skip rule: ✔ prompt extractor bỏ "things obvious from the code" + secret ([extract.md](../internal/extract/prompts/extract.md)); `remember` cấm "things already in the code/repo".
